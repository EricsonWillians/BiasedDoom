BiasedDoom vs UZDoom

This question comes up a lot, so here is the honest, comprehensive answer. Both projects are free software (GPLv3+), both descend from ZDoom/GZDoom, and both are legitimate homes for Doom's future — they are simply steered by different philosophies. Facts about UZDoom are taken from its own README and CONTRIBUTING files (UZDoom 5.1.0-pre, checked 2026-09-02); if anything here drifts out of date, file an issue.

Lineage and release model

UZDoom is the community's direct continuation of ZDoom and GZDoom — same codebase, same mod ecosystem, same savegame expectations, new 5.x version line, community governance. If your mental model is "GZDoom, continued", that is exactly what UZDoom aims to be.

BiasedDoom forked GZDoom at 4.15pre and deliberately diverges. It keeps classic Doom compatibility intact (your IWADs, WADs, DEHACKED and ACS maps all still run), but the roadmap is not "keep the past working" — it is "give modders a modern toolchain".

Technology direction

Models

BiasedDoom loads .gltf and .glb natively via fastgltf — skeletal animation, PBR metallic-roughness materials, direct Blender export — alongside the classic MD2/MD3/IQM/OBJ/UE1/voxel formats. UZDoom supports the classic formats only and has no glTF loader at all.

Graphics and post-processing

Both render through OpenGL, Vulkan and GLES; BiasedDoom switches between them live, without a restart. BiasedDoom then goes much further into image control, all menu-driven (Options → Display Options → Advanced): bloom with threshold, soft-knee and intensity controls, lens effects, vignette, chromatic aberration, film grain, sharpening, retro pixelation, CRT/VHS/NTSC output modes, tonemapping, color grading, SSAO and FXAA — plus searchable browsers for 38 lighting-style, 64 graphics, and 16 fog presets (Warm Cinematic, Horror Contrast, Neon Glow, Hellfire Glow, Void Dread…), optional sector-edge light bleed, and a menu-driven third-person camera with presets, shoulder offsets and collision padding. UZDoom carries the inherited GZDoom post-processing stack and does not prioritize this area.

Content generation

BiasedDoom ships deterministic procedural missions — mission graphs, five architectural themes, staged keys, reachable landmarks, sizes 1–80 — built for replayable horde-style play. UZDoom has no procedural generation.

Scripting and tooling

UZDoom's modding story is ZScript (with ACS and DECORATE), actively maintained and documented, plus the long-standing editor ecosystem.

BiasedDoom embeds a full CPython 3.12 interpreter as the primary scripting surface — live actor handles, a persistent display-list canvas, the actor registry, a DAP debug server, CI-friendly -scripttest mode — documented across this site (see API Reference and Examples). The stated direction is to deprecate ZScript in favor of Python; ACS remains supported so classic maps keep working. And the authoring loop runs through Heresy Editor, which scaffolds script workspaces, installs the type stub, generates trigger stubs, and surfaces Python errors in its log window.

The AI question

This is the sharpest philosophical split, and it is worth quoting UZDoom's position verbatim (CONTRIBUTING.md):

"No AI generated code of any kind may be submitted. This includes but is not limited to: code created by generative AI, modifications of code created by generative AI, code modified by generative AI (e.g. having it fix bugs in your code), code created with generative AI assistance… Any undisclosed use of generative AI will result in an organization-wide ban." — and the same for AI-generated art.

BiasedDoom takes the opposite path: AI-assisted development is encouraged, responsibly. That means disclosed use, human review and ownership of every line, and the same correctness bar as any other contribution — the engine's Python subsystem, its example suite, and parts of its artwork were developed this way in the open. We believe programmers learning to direct these tools well is part of the craft now; gatekeeping the tools away teaches nothing.

Neither stance is free: UZDoom's ban protects provenance and reviewer attention at the cost of turning away contributors who use modern tooling; BiasedDoom's openness demands stricter human review and a thick skin about provenance debates. Pick the one you can live with.

Philosophy and community values

UZDoom's stated core values are accessibility, player agency, and stability through backwards compatibility — a careful, conservative engine for the existing mod ecosystem. BiasedDoom's values are experimentation, authorship speed, and modern content pipelines — a lab for what Doom engines can become, while still loading your favorite IWADs and PWADs.
