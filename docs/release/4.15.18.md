# BiasedDoom 4.15.18

> **Superseded release candidate.** The `v4.15.18` source tag was pushed, but
> its packaging workflow did not publish a GitHub Release after a MinGW
> OpenGL-header build failure. The complete public release is
> [BiasedDoom 4.15.19](4.15.19.md), which includes this work and the
> packaging correction.

The 4.15.18 candidate is a feature, compatibility, and stability build. It
makes procedural Doom runs substantially more replayable, adds managed
companion co-op to every map type, and hardens sustained capture and large
classic weapon packs.

## Replayable Procedural Campaigns

- Every Doom-family procedural recipe now derives one of five automatic run
  profiles—Expedition, Assault, Infiltration, Circuit, or Siege. The profile
  changes the route rhythm, key order, branches, loops, encounters, rewards,
  arsenal cadence, and finale without adding a selector or making the run
  unfair.
- Levels now plan coherent stage shapes, landmark districts, material families,
  room contours, connection widths, and walkable terrain before UDMF is
  emitted. The result is more varied architecture—such as naves, courts,
  bastions, bridges, loading bays, and ritual pits—rather than a shared square
  room spine with a theme swap.
- Keys open their real manual keyed doors. Optional reveal/cache interactions
  are explicit player-use actions, and serialized navigation proofs reserve
  clear approaches for doors, stairs, pads, switches, rewards, and landmarks.
  When an embellishment cannot fit safely, the generator drops it instead of
  making ordinary space inaccessible.
- Completing a generated map unlocks **Next Random Run (Same Setup)**, which
  starts a new seed with the completed run's settings for an endless local or
  host-authored cooperative loop.
- Doom and Ultimate Doom use an IWAD-safe procedural roster, while Doom II can
  use its expanded roster. Heretic and Hexen procedural generation is
  intentionally deferred from this version because each needs its own game
  grammar.

## Companion Co-op and Bots

- **Options → Gameplay/Multiplayer → Companion Bots** now manages a central
  squad for ordinary and procedural maps. Start from zero, add a reviewed
  custom or random companion one at a time, edit each saved profile, remove one
  member, or dismiss the entire squad. Network hosts own roster changes while
  guests can inspect the authoritative result.
- Companions use the same bounded, map-agnostic navigation and combat-safety
  rules on authored and generated maps. They can route around safe corners,
  stairs, recognized doors, and lifts; avoid unsafe shots and hazards; and are
  physically passable to cooperative players so they cannot trap someone in a
  doorway or small room.
- A local companion squad enables co-op gameplay rules without turning a solo
  player into a second human participant. The classic Doom status bar therefore
  keeps its normal single-player portrait treatment for that local-only case,
  so its bright multiplayer backing cannot show through transparent custom
  mugshots such as Year Zero's. Real multiplayer keeps the standard
  player-colour backing.

## DECOHack, DSDHacked, and MBF21 Weapon Mods

- DSDHacked-format `DEHACKED` patches (`Doom version = 2021`) can now resolve
  sparse `[SPRITES]` IDs without expanding the old dense sprite-name table to
  the highest supplied number. This restores weapon sprites from
  DECOHack-based MBF21 mods that use conventional extended IDs such as `8000`.
- Extended IDs are accepted through the signed 32-bit range and stored in a
  sparse mapping. The mapping is capped at 262,144 distinct extended entries
  for predictable memory use; malformed, overflowing, or excess new entries
  are rejected safely with a diagnostic instead of allocating without bound.
- `tools/test-dehacked-extended-sprites.sh` provides a self-contained
  regression fixture for an `8000` ID, `INT_MAX`, more than 65,536 sparse
  entries, and overflow rejection. It does not redistribute any third-party
  mod assets.

This improves the DSDHacked/DECOHack sprite path, not every possible mod
interaction. Keep required resources in the mod author's documented order and
use the startup log when a patch still reports an undefined sprite. See
[classic-mod compatibility](../engine/mod-compatibility.md) for the exact
scope and diagnostics.

## Recording and Export Reliability

- PNG-sequence and raw RGB-AVI capture now include synchronized 48 kHz game
  audio: PNG takes receive a WAV sidecar and timestamped `ffconcat` sidecar;
  AVI parts carry PCM audio.
- Capture work remains deliberately bounded under slow storage or a delayed
  GPU. PNG samples can be skipped rather than building an unbounded backlog;
  AVI holds the latest completed image on its writer timeline so a sustained
  take retains its requested duration without retaining raw frames.
- OpenGL capture uses a bounded PBO ring and zero-wait retirement polling
  rather than a capture-driven `glFinish`. Vulkan records from a reusable
  final-present RGBA8 target. A capture that cannot recover stops with a
  visible failure instead of continuing to accumulate work.
- The Recording & Export menu exposes PNG compression choices, a clear capture
  status (`REC`, `FINALIZING VIDEO`, `VIDEO SAVED`, or `VIDEO FAILED`), and an
  F12/double-tap-F12 migration that preserves existing custom bindings.

See [recording and export](../engine/recording-and-export.md) for output
formats, storage budgets, audio scope, and the recommended variable-frame-rate
PNG workflow.

## Gameplay-Mod Stability

- The prediction rollback path now preserves valid late transient actors that
  older client-side ACS effects create while the player is predicted. This
  fixes the sector-list corruption behind Brutal Doom's high-density
  `ToggleFlashlight` path and limits repeated compatibility diagnostics per
  map.
- `tools/test-brutal-doom-flashlight.sh` exercises that path with a locally
  supplied Brutal Doom PK3; the repository does not package or redistribute
  third-party game data.

## Compatibility Notes

- The demo/network protocol advances for companion profile data and
  host-authored procedural-map transfer records. Use matching 4.15.18 builds
  for multiplayer, demo recording, and deterministic replay work; mixed-build
  sessions are not supported.
- A supported IWAD remains required and is not included with engine builds.
  Automatic IWAD discovery is read-only and does not change a game
  installation. See [IWAD discovery](../engine/iwad-discovery.md).
