# BiasedDoom 4.15.19

BiasedDoom 4.15.19 is the public release of the replayable procedural-run,
companion co-op, recording reliability, and classic-mod compatibility work.
It supersedes the unpublished `v4.15.18` packaging candidate.

## Packaging Correction

- Windows MinGW builds now include the engine's generated OpenGL loader before
  a Windows source can include the legacy system GL header. That makes the
  `GLsync` capture-fence type consistently available and restores the MinGW
  package build.
- This is a build-portability correction only; it does not change recorded
  output, save data, networking, or game behavior.

## Replayable Procedural Campaigns

- Every Doom-family recipe automatically chooses one of five deterministic run
  profiles: Expedition, Assault, Infiltration, Circuit, or Siege. Profiles
  change route rhythm, keys, encounter cadence, rewards, arsenal progression,
  landmarks, and finales while retaining fair manual-door progression.
- Planned stage shapes, district material families, room contours, connection
  widths, vertical routes, and collision-clear circulation lanes make levels
  read as places rather than repeated room grids. Navigation and key-state
  proofs take precedence over optional decoration.
- A completed generated map enables **Next Random Run (Same Setup)** for an
  endless fresh-seed loop. Doom and Ultimate Doom use IWAD-safe emission; Doom
  II retains its broader roster. Heretic and Hexen procedural generation is
  intentionally deferred for this release.

## Companion Co-op and Bots

- The central Companion Bots roster works on ordinary and procedural maps.
  Players can begin with zero companions, add reviewed custom or random
  profiles one at a time, remove an individual companion, or dismiss the
  entire squad. Network hosts own shared-roster changes.
- Companions use bounded, map-agnostic routing around safe corners, stairs,
  known doors, and lifts. They are physically passable, so they cannot trap a
  player in a doorway or small room.
- Local companion co-op preserves the normal single-player classic HUD
  treatment, including transparent custom mugshots such as Year Zero's.

## Recording and Mod Stability

- PNG sequences and raw RGB AVI captures include synchronized game audio while
  keeping GPU readback and writer work bounded under slow storage or delayed
  graphics work. OpenGL no longer forces a capture-driven `glFinish`; Vulkan
  uses a reusable final-present readback target.
- Sparse extended DECOHack/DSDHacked sprite IDs now support MBF21 weapon mods
  without allocating a dense table to the largest supplied ID. The mapping is
  bounded and rejects malformed or excessive data safely.
- Prediction rollback preserves valid late transient actors used by older
  client-side effects, fixing Brutal Doom's high-density flashlight crash path.

## Compatibility and Validation

- Use matching 4.15.19 builds for multiplayer, demo recording, and
  deterministic replay work. A supported IWAD remains required and is not
  included with engine packages.
- The release gate covers deterministic procedural generation, navigation and
  key-state proofs, Doom I/Doom II legality, bot behavior, prediction rollback,
  classic weapon patches, capture audio, and platform package builds.
